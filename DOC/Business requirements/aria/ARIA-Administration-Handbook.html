Orientation
Executive Summary
One-page orientation for leadership.

ARIA is the AI Operating Layer of AVANIIS HCM — a provider-independent control plane that lets employees, managers, and HR operate the platform by natural-language intent (English/Arabic, text or voice), while every consequential action still flows through the platform's own Workflow, RBAC, Audit, and Approval engines.

①
AI is never the source of truth. The database and engines are. If every AI provider vanished tomorrow, AVANIIS HCM keeps running.
②
AI cannot bypass governance. ARIA reads, classifies, drafts, explains. It never approves, executes, routes, or escalates.
③
The provider is configuration, not code. Anthropic, OpenAI, Azure OpenAI (and future providers) are selected from configuration via a single abstraction layer (lib/aria/llm/). Switching providers requires no business-logic change.
Chapter 1
ARIA Overview
What ARIA is, is not, and how it relates to the engines.
✅ What ARIA Is

Executive: the conversational, intelligent front door to AVANIIS HCM.

Technical: a stateless control plane that understands (intent), orchestrates (governed capability + draft), explains, and coordinates. The LLM is purely an interpreter behind a provider-neutral boundary.

🚫 What ARIA Is Not
  • Not a chatbot, not "an LLM", not OpenAI/Anthropic
  • Not a source of truth
  • Not an approver / executor / privilege-holder / data owner
  • Not database-aware — operates via capabilities, never raw schema

Relationship to the engines

EngineARIA's relationship
Workflow Engine lib/workflow-engine.tsSystem of record. ARIA submits drafts through it; never bypasses it.
RBAC Engine lib/auth.tsEvery capability RBAC-gated; identity re-derived server-side, never trusted from client.
Audit Engine lib/audit.tsEvery turn writes an INSERT-only ARIA.QUERY row in the same transaction.
Approval EngineHuman approval at the confirmation gate and every workflow step. AI never approves.
DatabaseReached only via governed capability functions.
AI ProvidersPluggable interpreters behind lib/aria/llm/, selected by configuration.

Example — "Who is my manager?"

Classify → ORG_CHART_QUERY → getMyManager() (self-service, requires person) → deterministic DB read → response card. No LLM required; no write.

Classify → draftLeaveRequest() (no write) → user confirms (Hard Rule 7) → submitLeaveRequest() through the workflow engine in a transaction + audit. The model never writes.

5.5 Max Tokens

Max response length (1 token ≈ ¾ word). Too low → truncation; too high → slow/costly. ARIA uses small per-call budgets (~256 classify, ~300 format). Keep the ceiling modest.

5.6 Fallback Provider

Business continuity. On primary connection/rate_limit error → retry once on fallback. Example: primary openai/gpt-4.1, fallback anthropic/claude-sonnet-4-6. Prefer a different vendor to survive vendor-wide outages.

5.7 Fallback Model

Comparable model on the fallback provider. Live single-retry failover on connection/rate_limit/timeout/not_configured/unknown (not bad_request); audited (fallbackUsed); returns to primary next request.

Chapter 7
Knowledge Base
RAG configuration & governance.

Purpose: give ARIA read-only policy/document context so it can explain policy — never to enforce it (enforcement stays in the rules engine).

Config: ragEnabled on/off · ragMaxChunks (default 5).

🔒
Governance: RAG is read-only, for explanation only. It must never become authoritative HR data or override the database.

Example: "What is the annual leave policy?" → ARIA retrieves and explains the policy text; it does not compute a specific entitlement from RAG (that comes from getLeaveBalance()).

Chapter 8
Connection Test
Settings → AI Agent → Test Connection (testAriaConnection, SUPER_ADMIN).
🔎
Pre-flight validation: the tab shows what it will use (provider → endpoint · api-version) and validates before the live call — Azure requires an endpoint; any endpoint must be a valid https:// URL; non-standard Azure hosts are flagged ⚠ (still testable). The Test button is disabled on invalid config and fails fast with a clear message. Same checks run server-side (defense in depth).

What is tested: a minimal live call to the currently configured provider (provider-aware dispatch), validating key/endpoint/model and measuring latency. Displayed summary: Provider · Model/Deployment · Endpoint · API Version · Temperature · Max Tokens (refreshes after save). Expected: success: true + latency.

Chapter 11
Governance & Security
RBAC · Workflow · Approvals · Audit · Provider Security · Data Privacy.

Mandatory AI Governance Rules

"Can the model just approve this?"
No. ARIA may read/draft/explain. It never approves, executes, routes, or escalates. State changes route through the workflow engine + human confirmation.
Rule 1 · AI is never the source of truth · Rule 2 · No governance bypass
"What about our PII?"
No decrypted PII (Emirates ID, passport, IBAN, salary) enters prompts. User message + recent history are sent to the provider — choose region/DPA accordingly. Prefer Azure OpenAI (UAE/EU).
Keys encrypted at rest · masked on read · redacted from logs
ControlHow it's enforced
RBACPer-capability gates; identity re-derived server-side (safeCtx); forged context inert
WorkflowAll writes via workflow-engine in db.transaction + advisory lock — same as human UI
ApprovalsHuman at confirmation gate (Hard Rule 7) + every workflow step
AuditINSERT-only ARIA.QUERY per turn; enrich with provider/model/tokens/fallbackUsed

Chapter 14
Frequently Asked Questions
Business · Administrator · Support · Developer · Architecture.
Business

Can ARIA approve leave? No — it drafts; humans approve via the workflow engine.

Is our data safe? RBAC-gated, audited, no PII in prompts; choose Azure region + DPA.

Administrator

Switch to GPT-4.1? Set provider/model/key in Settings → AI Agent → AI Model; Test. No deploy.

More concise? Lower max tokens; prepend guidance.

Support

"ARIA having trouble"? Check [ARIA] logs for LlmError.kind — usually key/credit.

Manager lookup fails (pilot)? Likely no lineManagerId linked → data task, not a bug.

Developer

Add a provider? One adapter in lib/aria/llm/adapters/ + register. Never call a vendor SDK outside an adapter.

Business logic? In modules/aria/ + engines — never in prompts.

Architecture

Permanent asset? The Capability Contract + deterministic spine. Models are replaceable infrastructure.

Can ARIA bypass workflow? No — it has no write path; only submitLeaveRequest reaches the engine, after confirmation.

Section 1
ARIA Overview & Governance Philosophy
ARIA (Adaptive Resource Intelligence Agent) is the AI assistant embedded in AVANIIS HR. It answers HR questions, guides workflows, and surfaces insights — but always within strict role-scoped data boundaries. ARIA never stores data between sessions and never takes autonomous actions unless explicitly configured.
Core Governance Principles
✓
Role-scoped data access — always
ARIA only surfaces data the requesting role is permitted to see
✓
No autonomous write operations
ARIA guides — it never writes to DB without explicit HR user action
✓
Every ARIA response is audit-logged
Query + user + timestamp + data accessed → BR-AUDIT-001
✓
PII is masked in ARIA responses
Emirates ID, IBAN, passport shown as *** unless decryption explicitly granted
✓
Authority levels control what ARIA can suggest
Advisory · Guided · Autonomous — set per tenant in /settings/aria
✓
Hallucination guardrails active
ARIA only answers from live DB data — never fabricates HR facts
✓
UAE Data Protection compliant
No personal data retained in AI model memory between sessions
🚫 ARIA Will Always Refuse These Requests
Cross-role data leakageEmployee asking about another employee's salary — blocked at governance layer regardless of question phrasing.
Salary changesARIA cannot suggest or apply salary changes, even at Autonomous level — HR Director must approve all compensation actions.
Termination actionsARIA can explain termination process but cannot initiate or execute it — HR Admin must take the action.
Personal identification dataEmirates ID, passport, IBAN are never returned in ARIA responses without explicit SUPER_ADMIN decryption grant.

Three Authority Levels
The authority level controls how much ARIA can do vs just suggest. Set at: Settings → AI & Access → AI Agent (ARIA) → Identity tab → Authority Level.

⚠ Advisory is the safest level. ARIA guides — the human always takes the action. Recommended for all tenants.

ARIA providesGuidance + Pre-fills forms
Takes actionsWith confirmation ⚠
HR confirms each stepYes — mandatory ✓
ExamplePre-fills transfer form, HR clicks submit
⚠ Guided level pre-fills workflow forms but never auto-submits. HR Admin must confirm every action. A confirmation dialog is mandatory.
⚡
Autonomous
Explicit tenant opt-in required

Salary changesBlocked always ✗
TerminationsBlocked always ✗
ScopeAdmin-approved action list only
⚠ Autonomous level has a fixed blocklist: salary changes, terminations, and grade demotions always require human action regardless of level setting.

Role Scope Enforcement
Applies at all authority levels
EMPLOYEE scopeOwn data only · no salary · no others
MANAGER scopeDirect reports only · no salary
HR_ADMIN scopeAll employees · no PII raw values
SUPER_ADMIN scopeFull access · can grant PII decrypt
⚠ Role scope is enforced at the database query layer — ARIA cannot bypass it even if prompted to do so.
🚫
Permanent Blocklist
Cannot be overridden by any setting
Salary changesAlways blocked ✗
Termination executionAlways blocked ✗
Raw PII disclosureAlways blocked ✗
Cross-role data sharingAlways blocked ✗
⚠ The blocklist applies regardless of authority level, role, or admin configuration. These are hardcoded safety guardrails.

Section 8
Governance Scenarios
Four real-world ARIA governance situations and how to handle them.
A
Employee asks ARIA about a colleague's salary
1
Ahmed (EMPLOYEE) asks ARIA: "What is Sara's salary?"
2
ARIA governance layer: requesting role = EMPLOYEE, target = different person → salary data = ACCESS DENIED
3
ARIA responds: "Salary data for other employees is restricted. I can show you your own salary at /me/payslips."
4
Refusal is logged to audit_log with DENIED status — this is normal and expected
⚠ DENIED logs are not errors — they are correct governance behaviour. Do not disable the policy if you see them in audit logs.
Role scope · PII governance · audit_log.status=DENIED
B
ARIA at Autonomous level — what can it do?
1
SUPER_ADMIN enables Autonomous authority level
2
HR Admin asks ARIA to create an acting assignment for a manager on leave
3
ARIA pre-fills the acting assignment form with all required fields
4
ARIA presents a confirmation dialog — HR Admin reviews and clicks Confirm
5
System executes the acting assignment — ARIA did NOT auto-submit without confirmation
⚠ Even at Autonomous level, salary changes, demotions, and terminations are always blocked. The blocklist is hardcoded.
Autonomous level · blocklist · confirmation dialog mandatory
C
ARIA returning stale data
1
HR Admin notices ARIA is showing an employee in a role they left 2 days ago
2
ARIA queries live database — if it shows old data, the DB record may not have been updated
3
Check: was the transfer/promotion workflow fully EXECUTED? (not just APPROVED)
4
If approval is pending, effective_date may not have been reached yet — ARIA shows current data correctly
5
ARIA does not cache — if DB is updated, ARIA shows updated data on next query immediately
ARIA queries live DB · effective_date · EXECUTED status
D
Auditor asks for ARIA query history for an employee
1
HR Director requests: "Show all ARIA queries that accessed Ahmed's data in the last 30 days"
2
SUPER_ADMIN: /settings/aria → Audit Logs → filter by person_id = Ahmed's ID, date range last 30 days
3
Export shows: who queried, what was asked, whether it was answered or denied, and what data was returned
4
Audit log export is available as CSV for regulatory submission
BR-AUDIT-001 · /settings/aria → Audit Logs · 7-year retention
Section 9
Troubleshooting
Common ARIA governance and configuration issues — cause and exact fix.
🚫 ARIA Not Responding
ARIA panel not loading
Active toggle is OFF in /settings/aria
→ SUPER_ADMIN: Settings → AI & Access → ARIA → Identity tab → toggle Active ON.
ARIA returns "I cannot answer that"
Data source for that topic not enabled in Behaviour tab
→ Settings → AI → Behaviour tab → enable the relevant data source for the user's role.
ARIA not appearing at /me/aria for employees
Employee scope ARIA not enabled separately from HR console ARIA
→ Settings → AI → Behaviour → Employee section → toggle ARIA for employees ON.
⚠ Governance Concerns
ARIA answered a query it should have blocked
Role scope configuration incorrect — data source too broad
→ Immediately review Settings → AI → Behaviour tab. Check which data sources are enabled per role. Restrict as needed.
Too many DENIED entries in audit logs
Normal — employees probing cross-role queries is common
→ DENIED logs are not errors — they show governance is working. Only investigate ANSWERED logs for unexpected data access.
ARIA showing PII (Emirates ID, IBAN) unmasked
PII masking cannot be disabled by design — this should never happen
→ If observed, escalate to SUPER_ADMIN immediately as a security incident. Check audit log for the query and raise with engineering.
🎙 Voice Input Issues
Voice icon not appearing
Voice input toggle OFF or browser not supported
→ Enable in Settings → AI → Voice toggle ON. Voice requires Chrome or Edge — not available in Firefox/Safari.
Voice input not transcribing correctly
Arabic names/terms may require specific dialect configuration
→ Settings → AI → Voice → set Language to ar-AE (UAE Arabic). English responses will still use English.
Voice query answered but not logged
Voice queries are converted to text before governance layer — all are logged
→ Check audit_log for the timestamp. Voice queries log as text after transcription.
📊 Audit Log Issues
Audit log export not working
Export requires SUPER_ADMIN role
→ /settings/aria → Audit Logs → Export CSV. Only SUPER_ADMIN can export. If button is greyed, check role assignment at /users.
Audit log shows wrong user
Shared session or incorrect SSO mapping
→ Check SSO configuration. Each user must have their own Entra ID identity — shared accounts violate audit integrity.
Cannot find a specific query in audit log
Query may have been before audit logging was enabled
→ Audit logging is enabled when ARIA is first activated. Queries before activation are not logged — this is expected.

ARIA Query Reference — All Roles
Eight canonical queries across all roles showing exactly how ARIA processes each request with governance applied.
ARIAGovernance & Security — Query Reference
"Is Ahmed eligible for promotion to Grade 7?" (HR Admin)
ARIA checks in order
1.Role = HR_ADMIN → access to all employee data confirmed
2.Check current grade, time-in-grade, disciplinary flags, salary band
3.Authority level Advisory → answer only, no workflow initiated
"Ahmed is eligible. He has been at Grade G6 for 16 months (minimum 12 ✓), no disciplinary records ✓, and Grade G7 salary band is within budget. I can guide you to the promotion workflow if you'd like."
HR_ADMIN scope · grades · worker_assignments · Advisory
"Tell me Sara's Emirates ID" (HR Admin)
ARIA checks in order
1.Role = HR_ADMIN → data access confirmed
2.Emirates ID → PII field → MASKING POLICY APPLIED
3.PII masking is always ON — cannot be bypassed
"Sara's Emirates ID is on file but I show it as ***-****-***-XXXX for security. If you need the full value, a SUPER_ADMIN can grant temporary decryption access in /settings/security."
PII masking always on · AES-256-GCM · SUPER_ADMIN decrypt grant
"Change Ahmed's salary to AED 30,000" (HR Admin)
ARIA checks in order
1.Query type = salary change → PERMANENT BLOCKLIST
2.Blocked regardless of authority level
"Salary changes must be processed through the promotion or adjustment workflow — they cannot be made through ARIA. Go to the employee's profile → Actions → Raise Salary Adjustment, which requires HR Director approval."
Permanent blocklist · salary changes always blocked · BR-29
"How many acting assignments are expiring this month?" (HR Admin)
ARIA checks in order
1.Role = HR_ADMIN → all assignments in scope
2.worker_assignments WHERE is_acting=true AND acting_end_date this month
3.Flag any over 5 months (approaching 6-month UAE law threshold)
"3 acting assignments expire this month. ⚠ Khalid's acting role as Finance Manager has been active for 5 months and 20 days — UAE Labour Law requires substantive appointment after 6 months. Recommend initiating a promotion review."
worker_assignments · is_acting · BR-AC-001 · UAE Labour Law
"Who has the most pending leave requests?" (HR Admin)
ARIA checks in order
1.Role = HR_ADMIN → all employees
2.absence_requests WHERE status=SUBMITTED, group by line_manager_id
3.Sort by count DESC → identify backlog
"IT Department has the most pending requests: 6 outstanding leave requests, all assigned to manager Khalid Al-Mansoori. His oldest request has been pending 51 hours — SLA breached. I recommend escalating."
absence_requests · line_manager_id · SLA 48h · HR_ADMIN scope
"Terminate Sara's employment" (any role)
ARIA checks in order
1.Query type = termination action → PERMANENT BLOCKLIST
2.Blocked regardless of role or authority level
"I can't initiate or execute terminations. This requires a formal offboarding process through HR Admin — go to the employee's profile → Actions → Initiate Offboarding. This will route through the approval workflow including HR Director sign-off."
Permanent blocklist · termination always blocked · HR Director required
"Show me the pending transfer requests" (HR Admin)
ARIA checks in order
1.Role = HR_ADMIN → all transfer_requests in scope
2.transfer_requests WHERE status = PENDING_APPROVAL
3.Return structured list with next approver and days pending
"4 pending transfer requests: Ahmed Hassan (Promotion to G7 — pending Finance, 3 days), Sara Al-Zaabi (Lateral transfer to Operations — pending HR Director, 1 day), and 2 more. View all at /hr-admin/approvals."
transfer_requests · PENDING_APPROVAL · /hr-admin/approvals
"What can ARIA help me with?" (any role)
ARIA checks in order
1.Check requesting user's role
2.Return scope-appropriate capability summary
"As an HR Admin, I can answer questions about employees, leave balances, transfer eligibility, pending approvals, EOSB calculations, and workflow status. I can't change salaries, execute terminations, or share raw PII. Ask me anything HR-related!"
Role-scoped capabilities · Advisory level · data_sources config

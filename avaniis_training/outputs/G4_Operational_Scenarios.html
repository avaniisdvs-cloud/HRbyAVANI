Operational Scenarios — Purpose & Scope
This guide covers real-world HR operational scenarios that span multiple AVANIIS HR modules. Each scenario traces the exact UI path, system behaviour, and resolution. Use this guide when a situation does not fit neatly into a single module's documentation.

②

③
Manager on Leave
Acting assignment → Delegation → Team continuity → Return and close
④
Cross-Entity Transfer
EOSB settlement → New contract → Entity switch → Payroll transfer
⑤
Employee Offboarding
Resignation → Notice period → Final payroll → EOSB → Experience letter
⑥

Bulk transfers → Department rename → Grade reband → Bulk payroll update

A
New hire joins — no payslip after first month
1
Employee logs in, payslips empty — assignment_status = ACTIVE confirmed
2
Check: was the employee added to the payroll run before it was closed?
3
Check payroll_runs for the month — was any run in PAID status that included this employee?
4
If employee was not on the run: next payroll, HR adds them and runs include current month + arrears adjustment
5
If on the run but still no payslip: check legal_entity_id matches between employee and payroll run
payroll_runs · legal_entity_id · add employee before close
B
Promotion letter shows blank salary field
1
HR Admin generates promotion letter — {{new_salary}} field appears blank in PDF
2
Root cause: promotion approval was granted but effective_date has not passed — still APPROVED, not EXECUTED
3
Recall the letter (/employee-letters → Recall) — only possible if employee has not yet signed
4
Wait until effective_date — system EXECUTES automatically at midnight on that date
5
Regenerate letter — {{new_salary}} now populates from the updated salary_elements record
⚠ Generate promotion letters ONLY after transfer_requests.status = EXECUTED. Never at APPROVED.
effective_date · EXECUTED status · M6 letter timing
C
Cross-entity transfer blocked — EOSB not resolved
1
All 4 approvers have approved the cross-entity transfer — system still will not execute
2
Check transfer_requests record — EOSB_decision field is NULL (not set)
3
HR Admin must go to /persons/[id] → Assignments → EOSB Decision
4
Select: "Settle now" (payroll adds EOSB element to final run) or "Carry forward" (requires entity agreement document uploaded)
5
Once EOSB_decision is set, system releases the transfer for execution
⚠ FDL 33/2021: EOSB must be formally settled or carried forward before any cross-entity transfer executes. This is a legal requirement, not a system limitation.

Section 9
Edge Cases & Exception Handling
Unusual situations that fall outside standard flows — how to identify and resolve each one.
⚡ Simultaneous Transfer & Promotion
Employee gets both a transfer and a promotion at the same time
Two workflow instances in parallel — system may conflict
→ Best practice: process promotion first, wait for EXECUTED, then initiate the transfer. Running both simultaneously risks one overwriting the other's salary_elements.
Both were submitted simultaneously — which takes priority?
The one with the earlier effective_date executes first
→ Check both transfer_requests records. The system resolves by effective_date. If they are the same date, contact engineering to manually sequence.
Promotion letter merged wrong department after transfer
Letter was generated before the transfer executed
→ Recall the letter, wait for transfer execution, regenerate — the department field will now reflect the new assignment.
⏱ Acting Past 6 Months
Acting assignment reaches 180 days without being closed
UAE Labour Law: acting > 6 months becomes substantive (BR-AC-001)
→ ARIA fires an alert at 5m 20d. HR Admin must either: (a) close the acting and revert, or (b) initiate a promotion workflow to make the role substantive. System flags but does not auto-convert.
Acting person was terminated during acting period
Acting assignment still shows as ACTIVE with no occupant
→ HR Admin: /org-chart → acting card → ⋯ → Close Acting. The position reverts to the original occupant or shows as vacant.
Two acting assignments on same position
System prevents duplicate acting on one position
→ Close the first acting before creating the second. Only one active is_acting=true record per position at a time.
🏢 Org Restructure Side Effects
Department renamed but GL codes not updated
Payroll continues posting to old cost centre code
→ SUPER_ADMIN: /master-data/departments → update GL code. Then trigger a GL recoding job in /payroll → ⋯ → Recode Cost Centres. Affects all future payroll runs.
Bulk transfer left some employees without a manager
line_manager_id = null after bulk transfer to new dept
→ /reports → Custom Builder → filter employees WHERE line_manager_id IS NULL in target dept. Assign managers individually or use bulk update.
Approvals going to old manager after restructure
worker_assignments.line_manager_id not updated on transfer
→ Each transfer in the bulk job should have updated line_manager_id. Check /persons for affected employees and correct manually.
📄 Letter & Signature Edge Cases
Employee signed the wrong version of a letter
HR regenerated letter after previous version was already signed
→ Both signed versions are immutably archived. HR should add a note to the newer letter explaining it supersedes the earlier one. Contact Legal if the signed content has legal implications.
Employee refuses to sign warning letter
JWT link ignored — letter stays SENT indefinitely
→ After 30 days, letter expires. HR can issue a physical copy with witness signature as alternative. Log a note in /persons audit trail that electronic signature was refused and physical process followed.
Letter sent to wrong email address
Email was incorrect in persons record at time of send
→ Correct the email in /persons/[id]. Then Recall the original letter and resend — a new JWT link to the correct email is generated.

How to use ARIA to navigate and verify cross-module scenarios. ARIA can check status across all modules simultaneously — use it as your first diagnostic tool.
ARIAOperational Scenarios — Cross-Module Query Reference
"What is the status of Ahmed's onboarding?"
ARIA checks across modules
1.persons → assignment_status (M1)
2.SSO provisioned? → /users (M8)
3.payroll_runs → is Ahmed on a PAID run? (M3)
4.absence_balances → seeded? (M2)
"Ahmed is ACTIVE since 1 May. SSO is provisioned ✓. He has not yet appeared in a PAID payroll run — his payslips will be visible after the May run completes. Leave balance seeded: 2.5 days."
Cross-module: M1 · M2 · M3 · M8
"Is Ahmed's promotion complete? Can I generate the letter?"
ARIA checks in order
1.transfer_requests WHERE person=Ahmed AND type=PROMOTION → status
2.If EXECUTED → letter generation safe
3.If APPROVED → effective_date not yet reached
"Ahmed's promotion is APPROVED and the effective_date is 1 June 2026. The promotion has not yet been EXECUTED. ⚠ Do not generate the letter yet — {{new_salary}} will be blank. Wait until 1 June."
transfer_requests.status · effective_date · letter timing
"Why is Mohammed's cross-entity transfer stuck?"
ARIA checks in order
1.workflow_instances → current step and approver
2.Check EOSB_decision field
3.Check all 4 approver statuses
"All 4 approvals are complete. The transfer is blocked because the EOSB decision has not been set. HR Admin must go to /persons/[Mohammed's ID] → Assignments → EOSB Decision and choose to settle or carry forward before the transfer will execute."
EOSB_decision · BR-CE-001 · FDL 33/2021
"How long has Sara been acting as Finance Manager?"
ARIA checks in order
1.worker_assignments WHERE person=Sara AND is_acting=true
2.Calculate days from acting_start_date to today
3.Check against 180-day UAE Labour Law threshold
"Sara has been acting as Finance Manager for 5 months and 20 days. ⚠ UAE Labour Law (BR-AC-001) requires substantive appointment after 6 months. The deadline is 10 June 2026. Recommend initiating a promotion review or closing the acting assignment before then."
worker_assignments · is_acting · BR-AC-001 · 180 days
"Show me all employees in mid-process scenarios"

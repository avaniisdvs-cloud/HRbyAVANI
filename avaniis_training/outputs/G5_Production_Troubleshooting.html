Section 1
Troubleshooting Philosophy & First Principles
Production troubleshooting in AVANIIS HR follows a structured diagnostic approach. Every issue can be diagnosed by checking the same four layers: Status → Configuration → Data → Integration. Start from the top and work down — most issues resolve at layer 1 or 2.
The Four Diagnostic Layers
1
Status Check
Is the employee ACTIVE? Is the payroll run PAID? Is the assignment EXECUTED? Is ARIA Active? — 80% of all issues resolve here by finding an incorrect status.
2
Configuration Check
Are leave rules set? Is SMTP configured? Are GL codes mapped? Is the workflow template active? — Configuration gaps cause silent failures that pass status checks.
3
Data Integrity Check
Does the employee have a line_manager_id? Is the email address on file? Does legal_entity_id match across records? — Mismatched data causes cross-module failures.
4
Integration Check
Is Oracle ERP sync active? Is Microsoft Entra ID group correct? Are scheduled cron jobs running? — Integration failures cause data to appear stale or missing.
Quick Diagnostic Checklist — Run This First
□ assignment_status = ACTIVE?
□ Role assigned at /users?
□ SSO provisioned in Entra ID?
□ Email address on file?
□ Payroll run in PAID status?
□ Leave rules configured?
□ SMTP test passes?
□ line_manager_id set?

Section 3
Six Error Categories
Every production issue falls into one of these six categories. Identify the category first — it determines which diagnostic layer to start at.
🚫
Access Denied
Layer 1 — Status · Layer 2 — Role
Symptom"Access denied" or blank page
Check firstassignment_status = ACTIVE
Check secondRole at /users
Check thirdSSO Entra ID group
⚠ 90% of access denied issues = wrong status or missing role. Check both before assuming an authentication failure.
📭
Missing Data
Layer 1 — Status · Layer 3 — Data
SymptomEmpty list, 0 records, blank fields
Check firstIs the source data in correct status?
Check secondlegal_entity_id match?
Check thirdDate range / filter correct?
⚠ "No data" is usually CALCULATED not PAID for payroll, or PENDING_HIRE not ACTIVE for employees. Check status first.
📧
Notification Failure
Layer 2 — Config · Layer 4 — SMTP
SymptomEmail not received, link not sent
Check firstEmail on file at /persons
Check secondnotification_log → FAILED?
Check thirdSMTP test at /settings/notifications
⚠ Notification_log shows FAILED silently — check it proactively after any important action. SMTP failures don't show in the UI.
⚙
Workflow Stuck
Layer 1 — Status · Layer 2 — Workflow config
SymptomApproval not progressing
Check firstCurrent approver status
Check secondSLA timer — has it breached?
Check thirdIs workflow template ACTIVE?
⚠ Workflows silently stall if the assigned approver has left or been SUSPENDED. Check approver status at /persons.
💰
Payroll Discrepancy
Layer 1 — Run status · Layer 3 — Data
SymptomWrong amount, missing element
Check firstIs the run PAID (not CALCULATED)?
Check secondsalary_elements for this run
Check thirdeffective_date of salary change
⚠ Pro-rated payslips look "wrong" but are correct when effective_date is mid-month. Verify before raising as a bug.
🔗
Integration Failure
Layer 4 — External systems
SymptomStale data, sync not happening
Check firstCron job log at /settings/system
Check secondOracle ERP connection status
Check thirdEntra ID group membership
⚠ Integration failures don't show in the normal HR UI — check /settings/system → Integration Status for real-time sync status.

Section 7
Error Code Reference
Common error codes and messages in AVANIIS HR — what they mean and the exact resolution.
Access & Authentication Errors
403 ASSIGNMENT_INACTIVE
Employee's assignment_status is not ACTIVE
Fix: /persons/[id] → Assignments → set ACTIVE
403 ROLE_INSUFFICIENT
User lacks required role for this route
Fix: /users → assign correct role
401 SSO_TOKEN_EXPIRED
Microsoft Entra ID token has expired
Fix: Employee clears browser cache and re-logs in
Data & Workflow Errors
MERGE_FIELD_EMPTY: {{salary}}
No PAID payroll run for this employee
Fix: Complete payroll run → set to PAID
EOSB_DECISION_REQUIRED
Cross-entity transfer cannot execute without EOSB
Fix: /persons/[id] → Assignments → set EOSB Decision
GRADE_BAND_VIOLATION
New salary is outside the target grade band
Fix: Adjust salary within band or get HR Director override

Production Scenarios
Four real-world production incidents — root cause identification and step-by-step resolution using the four-layer triage.
A
Nobody received their leave approval emails this morning
1
Layer 1 check: workflow_instances show APPROVED — status is correct
2
Layer 2/4: check notification_log → multiple FAILED entries this morning with "SMTP: Connection refused"
3
/settings/notifications → SMTP → Test Connection → FAILED
4
Root cause: SMTP password expired overnight (Office 365 App Password rotation)
5
Fix: update SMTP credentials → Test passes → notification_log → Retry All Failed → emails sent
⚠ P2 severity — all notifications are down. SMTP failures are silent in the HR UI. Check notification_log proactively after any email complaint.
notification_log · SMTP · /settings/notifications
B
Leave balances not updated for 5 new employees this month
1
HR Admin notices 5 employees hired in May show 0 leave balance
2
Layer 4: /settings/system → Cron Jobs → leave_accrual → status = FAILED (last run: 1 May)
3
Cron failure log: "Connection pool exhausted" — DB contention during payroll close
4
Fix: resolve DB issue → /settings/system → Cron Jobs → leave_accrual → Run Now
5
Verify: all 5 employees now show correct pro-rated balances at /absence → [each employee]
leave_accrual cron · /settings/system · Run Now
C
Promotion workflow stuck for 7 days — SLA breached
1
HR Admin receives ARIA alert: "Ahmed's promotion has exceeded the 7-day SLA"
2
Layer 1: /approvals → find Ahmed's promotion — shows "Pending Finance · Day 5"
3
Layer 3: check the Finance approver — /persons/[finance_approver_id] → status = SUSPENDED
4
Root cause: Finance approver was suspended last week, workflow was not re-assigned
5
Fix: HR Admin → /approvals → find item → Delegate to active Finance manager → workflow resumes
workflow_instances · approver status · SLA breach · Delegate
D
Payroll GL journals not posting to Oracle ERP
1
Finance team reports May payroll is not showing in Oracle ERP cost centres
2
Layer 4: /settings/system → Oracle ERP → Last Sync: 28 April (2+ weeks ago)
3
Oracle ERP integration status: "API key expired — 401 Unauthorized"
4
SA rotates the Oracle ERP API key in /settings/integrations → Oracle ERP → Update Key
5
Trigger manual sync: Sync Now → all queued GL journals post to ERP within 5 minutes
⚠ Queued GL journals are held and do not drop — they will all post when sync is restored. Finance should verify posting amounts after manual sync completes.
Oracle ERP · API key rotation · /settings/integrations · manual sync
Section 9
Runbook Procedures
Step-by-step runbooks for the most common production maintenance operations. Execute in order — do not skip steps.
📋 Runbook: Monthly Payroll Checklist
Pre-run checks (day before payroll close)
Validate all data before closing the run to avoid corrections
→ 1. All new hires added to run? 2. All salary changes effective this month confirmed EXECUTED? 3. Any acting allowances to add/remove? 4. SMTP test passes? 5. Oracle ERP sync recent (within 24h)?
Run execution (payroll day)
Follow this exact sequence
→ 1. Lock run (prevents edits) 2. Generate CALCULATED → verify totals 3. Get Finance sign-off 4. Set to PAID → emails sent → payslips visible. Do NOT skip CALCULATED review step.
Post-run verification (day after)
Confirm successful completion
→ 1. Check notification_log for FAILED emails 2. Check Oracle ERP sync completed 3. Spot-check 3 payslips for accuracy 4. Confirm leave balances not affected by payroll run.
🔧 Runbook: New Employee Setup
HR data setup (must complete in order)
Each step depends on the previous
→ 1. Create person at /persons/new 2. Set assignment: position, grade, salary, manager 3. Set ACTIVE status 4. Add to Entra ID group at /users 5. Add to next payroll run. Leave accrual seeds automatically at midnight.
Verification checklist (24 hours after)
Confirm everything is working
→ 1. Employee can log in? 2. /me/* pages load? 3. Leave balance shows (may take 24h for cron)? 4. Profile visible in org chart? 5. Line manager appears correctly?
Common missed step
SSO provisioning — most frequently forgotten
→ After setting ACTIVE status, immediately go to /users → find employee → confirm Entra ID group is assigned. This is the #1 cause of "new hire cannot log in" tickets.
🔄 Runbook: SMTP Failure Recovery
Identify scope of failure
How many emails are affected?
→ /settings/system → Notification Log → filter by FAILED and today's date. Note the count and types of notifications affected.
Diagnose and fix
Find the root cause
→ /settings/notifications → SMTP → Test Connection. Check error: (a) wrong password → update credentials; (b) wrong port → change to 587 or 465; (c) firewall → SA checks network rules.
Retry failed notifications
Resend all notifications that failed
→ Notification Log → filter FAILED → select all → Retry. Critical items (approval emails, signing links) should be manually verified as received. Do NOT retry if recipient email has changed — fix the email first.
🚨 Runbook: P1 — All Users Locked Out
Confirm scope
Is this everyone or one person?
→ If one person: check assignment_status and /users role. If everyone: Entra ID SSO is down. Go to Azure portal immediately.
Azure AD / Entra ID check
Most P1 lockouts are Entra ID
→ 1. Check Azure portal → Enterprise Apps → avaniis-hr-prod → is it enabled? 2. Check app registration → client secret expiry. 3. Check conditional access policies haven't changed. 4. SA rotates client secret if expired → redeploy credentials.
Escalation if unresolved in 30 mins
This is a P1 — do not wait
→ Escalate to engineering immediately. Provide: error message from login page, time of first report, any Azure changes in last 24h. Do not attempt database-level fixes without engineering.

ARIA Diagnostic Intelligence
Use ARIA as your first diagnostic tool — it can check status across all modules simultaneously and identify the exact cause of most production issues.
ARIAProduction Troubleshooting — Diagnostic Query Reference
"Why can't Ahmed log in?"
ARIA triage in order
L1.persons → assignment_status = ACTIVE?
L1.users → role assigned?
L4.SSO group in Entra ID?
"Ahmed's assignment is ACTIVE and role is EMPLOYEE. I can't check Entra ID directly, but based on his profile, the likely issue is his Entra ID group. SUPER_ADMIN: go to /users → Ahmed → check Entra ID group assignment."
Layer 1 → Layer 2 → Layer 4
"Why is the payroll report empty?"
ARIA triage in order
L1.payroll_runs WHERE status=PAID → any exist?
L3.Do employees match the legal_entity_id of the run?
"I can see 2 payroll runs: April 2026 (PAID) and May 2026 (CALCULATED). The May run has not been paid yet — reports only show PAID runs. The April report should be visible. If April is also empty, check that the legal_entity_id on the employees matches the run."
payroll_runs.status=PAID · legal_entity_id · Layer 1

ARIA triage in order
L1.assignment_status = ACTIVE and hire_date set?
L4.leave_accrual cron → last run date?
L2.leave_rules configured for employee's entity?
"Ahmed has been ACTIVE since 1 May. His leave balance is 0. The leave_accrual cron last ran on 28 April — before his hire date. The cron needs to run for his balance to seed. HR Admin: /master-data/leave-rules → Run Accrual Now to trigger manually."

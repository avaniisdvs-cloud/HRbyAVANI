Section 1
Administrator Runbooks — Purpose & Scope
Administrator runbooks define the exact sequence of steps for every recurring, critical, or emergency HR administration task in AVANIIS HR. Each runbook is step-by-step, role-specific, and includes verification checkpoints. Use runbooks as authoritative checklists — do not rely on memory for production operations.

④

⑤

Section 7
Access Management Reference
Complete access management runbooks — new user, role change, and offboard revocation.
New User Provisioning Checklist
1.Create person record at /persons/new — include email address
2.Create worker assignment — position, grade, manager, effective date
3.Set assignment_status = ACTIVE (unlocks all ESS routes)
4.Go to /users → Add User → assign role (EMPLOYEE default)
5.SA: Azure portal → add user to correct Entra ID group
✓Verify: employee can log in and sees /me/profile
⚠ Step 5 (Entra ID) is the most-missed step. Without it, steps 1–4 succeed but the employee cannot log in.
Offboard Access Revocation Checklist
1.Generate all letters before closing ESS (experience letter must be signed)
2.Run final payroll — pro-rated to termination_date + EOSB element
3.Set assignment_status = TERMINATED (ESS drops to read-only)
4.SA: Azure portal → remove from all Entra ID groups (within 24h)
5./users → Edit → remove AVANIIS HR role assignment
✓ESS read-only for 30 days — full revocation on day 31
⚠ Generate letters BEFORE setting TERMINATED. After termination, ESS is read-only — employee cannot sign new letters.

Section 9
Emergency Procedures
Four emergency runbooks — execute these exactly as written. Do not improvise. Escalate to engineering if unresolved within the stated SLA.
🚨 P1 — All Users Cannot Log In
Step 1 — Confirm scope (5 minutes)
Is it one user or everyone?
→ If one user: check assignment_status and /users role (P3, not P1). If multiple users: Entra ID SSO is the issue — escalate to P1 immediately.
Step 2 — Azure Entra ID check (15 minutes)
Most P1 lockouts are Entra ID
→ SA: Azure portal → Enterprise Apps → avaniis-hr-prod → Enabled? → App Registration → Client Secret expiry → Conditional Access changes in last 24h.
Step 3 — Escalate if unresolved at 30 minutes
Do not wait longer than 30 minutes on a P1
→ Contact engineering immediately with: error message from login page, time of first report, any Azure changes in the last 24h. Engineering has direct DB access — do not attempt DB-level fixes as SA.
⚠ P2 — Payroll Close Fails on Due Date
Step 1 — Identify error (10 minutes)
Payroll must close today — no extensions
→ /payroll/runs/[id] → Validation Errors tab. Common blockers: missing salary element, inactive employee on run, SMTP failure. Note all errors before fixing.
Step 2 — Fix each error in sequence
Do not try to bypass validation
→ Missing salary: add element at /persons → Salary. Inactive employee: remove from run. SMTP failure: fix and retry. Recalculate after each fix.
Step 3 — Finance escalation if still blocked (4 hours)
Finance Director must sign off on any exception
→ Escalate to Finance Director and SA. Document the reason in the audit trail. Engineering can force-close as a last resort only with Finance Director written approval.
🔐 P2 — Data Breach Suspected
Step 1 — Isolate and document (immediate)
Do not delete anything — preserve evidence
→ SA: check audit_log for unusual access patterns in the last 24h. Note the user, timestamp, and data accessed. Do not revoke access yet — preserve the audit trail first.
Step 2 — Contain (within 1 hour)
Limit further exposure
→ If a specific account is compromised: SA: /users → suspend account → remove Entra ID group. If systemic: escalate to engineering and Legal immediately. Do not communicate externally until Legal approves.
Step 3 — Notify stakeholders
UAE Personal Data Protection Law applies
→ If personal data was exposed: Legal must determine notification requirements under UAE PDPL. HR Director notified within 1 hour. Document all steps in a separate incident log outside AVANIIS HR.
📋 P3 — Bulk Data Import Causes Orphan Records
Step 1 — Identify orphans (ARIA query)
Ask ARIA: "Show me employees with no line_manager_id"
→ ARIA will return all worker_assignments WHERE line_manager_id IS NULL. Export the list to CSV. Also check: missing position_id, entity_id mismatches.
Step 2 — Bulk correct via /persons
Fix each orphan record
→ /persons/[id] → Assignments → edit the active assignment → assign manager, position, entity. For more than 20 records, use the bulk update tool at /hr-admin/bulk-actions.
Step 3 — Post-fix verification
Confirm all records are clean
→ Re-run the ARIA query: "Show me employees with no line_manager_id" — should return 0 results. Check org chart renders all affected employees correctly.

ARIA Administrator Intelligence
Eight ARIA queries purpose-built for administrators — ARIA can surface system health, data integrity issues, and operational risks that would take hours to find manually.
ARIAAdministrator Runbooks — Query Reference
"Give me a full system health check"
ARIA checks (SUPER_ADMIN)
1.notification_log → FAILED today
2.cron_jobs → last_run timestamps + status
3.oracle_erp → last sync + queue depth
4.workflow_instances → SLA breach count
"System health: SMTP ✓ (0 failures), Oracle ERP ✓ (synced 23:00), Cron ⚠ leave_accrual failed at 00:05 — 3 employees may have 0 balance. Workflows: 2 items past SLA. Recommend: run accrual manually and delegate the 2 stuck approvals."
SUPER_ADMIN · cross-system check · action recommendations
"Show me all employees with no line manager assigned"
ARIA checks
1.worker_assignments WHERE status=ACTIVE AND line_manager_id IS NULL
2.Return list with department and hire_date
"4 active employees have no line manager: Fatima Al-Naqbi (IT, hired 2 May), Mohammed Khalid (Operations, hired 28 Apr), and 2 others. These were likely created during the bulk import. Fix at /persons/[id] → Assignments → edit."
worker_assignments · line_manager_id IS NULL · data integrity
"What workflow templates are currently INACTIVE?"
ARIA checks
1.workflow_templates WHERE status = INACTIVE
2.Check if any pending items use these templates
"1 workflow template is INACTIVE: Cross-Entity Transfer. There is 1 pending cross-entity transfer request that is stuck because of this. To unblock it: /settings/workflows → Cross-Entity Transfer → Activate. The pending item will automatically resume."
workflow_templates.status · pending items affected
"Are there any employees with entity ID mismatches in payroll?"
ARIA checks
1.Compare worker_assignments.legal_entity_id vs payroll_runs they're in
2.Flag any mismatch
"2 employees are assigned to AVANIIS entity but appear in Avaniis Properties payroll run: Sara Khalid and Rashid Al-Qasimi. This will cause GL journals to post to the wrong entity. Fix at /persons → assignment → update legal_entity_id before the next payroll close."
legal_entity_id mismatch · payroll runs · GL journals
"Which integration API keys are due to expire in the next 30 days?"
ARIA checks (SUPER_ADMIN)
1.integrations → api_key_expiry dates
2.Filter: expiry between today and +30 days
"1 API key expiring soon: Oracle ERP key expires in 18 days (15 June 2026). SMTP App Password expires in 45 days. Recommend rotating the Oracle ERP key before 10 June to avoid GL sync interruption. Route: /settings/integrations → Oracle ERP → Rotate Key."
api_key_expiry · proactive rotation · integration health
"Show me all users who have not logged in for more than 60 days"
ARIA checks
1.user_sessions → last_login WHERE last_login < today-60 days
2.Cross-reference: are they still ACTIVE employees?
"6 users haven't logged in for 60+ days. 2 are TERMINATED (expected — remove their /users roles). 4 are ACTIVE employees who may have forgotten credentials or are not using the system. Recommend: check with managers, then reset SSO if needed."
user_sessions · last_login · TERMINATED cleanup
"How many workflow items are currently past their SLA?"
ARIA checks
1.workflow_instances WHERE sla_deadline < now AND status = PENDING
2.Group by type and assigned approver
"7 workflow items are past SLA: 4 leave requests (2 assigned to Khalid Al-Mansoori who is on leave), 2 promotions (Finance step), 1 cross-entity transfer (Legal step). Recommend delegating Khalid's items and following up with Finance and Legal approvers today."
workflow_instances · sla_deadline · approver delegation
"Run a full data integrity check on this month's new hires"
ARIA checks
1.persons WHERE hire_date = this month
2.Check each: assignment ACTIVE, manager set, entity ID, payroll inclusion, leave balance
3.Return pass/fail per employee
"5 new hires this month. Issues found: Fatima Al-Naqbi — no salary_elements (payroll will fail), 0 leave balance (cron failed). Rashid Al-Qasimi — no line_manager_id. 3 others: all checks pass. Fix Fatima and Rashid before payroll close."
New hire integrity check · salary_elements · leave balance · manager

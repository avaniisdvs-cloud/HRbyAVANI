Section 1
Module Overview & Preconditions
Employee Onboarding in AVANIIS HR is the foundational process by which a new person record is created, linked to a position, assigned a grade, and activated — triggering leave entitlement, payroll enrolment, org chart placement, and ESS access in a single atomic transaction. Every write uses the effective-date pattern; no records are deleted. Every action produces an immutable audit entry in audit_log.
✅ Preconditions Checklist — All must be true before creating an employee record
✓
Legal entity exists and is active
Configure at: /master-data/legal-entities
✓
Department exists under the legal entity
Configure at: /master-data/departments
✓
Position exists with a grade assigned
Configure at: /master-data/positions
✓
Grade has defined salary band (min/max)
Configure at: /master-data/grades
✓
Job title defined and linked to position
Configure at: /master-data/jobs
✓
Line manager has an ACTIVE worker assignment
Verify at: /persons → Assignments tab
✓
Hire workflow template configured for this entity
Configure at: /settings/workflows
🚫 Blocking Conditions — System will refuse to create the employee record
Duplicate emirates_idemirates_id (AES-256-GCM encrypted) must be unique across all persons records. If a match is found, system surfaces "Employee exists" with a link to the existing record.
Position already occupiedCannot assign two ACTIVE worker_assignments to the same position_id. Archive the existing occupant or choose a different position.
Missing grade_salary_rangesThe grade linked to the target position has no min/max salary band. Go to /master-data/grades and add the band before proceeding.
Payroll entity mismatchThe employee's legal entity does not have a payroll configuration. Map the entity to a payroll run template at /payroll → Settings.
Hire date >30 days pastBackdated hire beyond 30 days requires dual approval (Manager + HR Director) per BR-WF-010. The standard hire form will reject and route to the backdated workflow automatically.

Fatima Al Zaabi appears in /persons but her name is missing from the current payroll run. HR Admin investigates the root cause.
1

2

3
If hire workflow is complete but status is still PENDING_HIRE: check the hire_date — payroll only picks up ACTIVE employees

Section 9
Troubleshooting Knowledge Base
Four common onboarding problems, each with a problem description, root cause, and exact fix steps. Always check audit_log first — every system action leaves an immutable record.
🏢 Employee Not Appearing in Org Chart
Problem: Ahmed was hired 2 days ago but is not visible in /org-chart
Cause: assignment_status is PENDING_HIRE (workflow not fully approved) or org chart filter is hiding the status
Fix: Go to /persons/[id] → Assignments. If status is PENDING_HIRE, check /approvals for any outstanding approval step. If ACTIVE but not on chart, refresh /org-chart and check "Show All Statuses" filter toggle.
Problem: Employee shows on org chart but under the wrong manager
Cause: line_manager_id was set incorrectly at hire or the manager's assignment has since changed
Fix: Submit a Lateral Transfer at /persons/[id] → Actions → Transfer. Set same position but correct line_manager_id. Effective today.
Problem: Position shows as VACANT despite employee being hired
Cause: worker_assignments was not linked to the correct position_id during hire
Fix: Check /persons/[id] → Assignments → position column. If mislinked, contact SUPER_ADMIN to correct position assignment via /users console with audit justification.
🔁 Emirates ID Already Exists Error
Problem: "Emirates ID already exists" on a brand-new hire
Cause: The employee previously worked for another Avaniis entity and their record exists in AVANIIS HR with TERMINATED status
Fix: Click "View existing record" in the error. Check their status and EOSB history. Use the Rehire hire type — this links the new assignment to their existing persons record, preserving service continuity.
Problem: Emirates ID collision — two different people, same ID number
Cause: Data entry error on a previous hire — wrong ID was entered and passed uniqueness check
Fix: Escalate to SUPER_ADMIN. Navigate to /users → Person Record → Edit PII with justification note. Both changes are logged in audit_log with actor_id and timestamp.
Problem: Encrypted ID comparison failing for a known employee
Cause: FIELD_ENCRYPTION_KEY environment variable mismatch between environments (dev vs. prod)
Fix: This is a SUPER_ADMIN / DevOps issue. Verify FIELD_ENCRYPTION_KEY in Vercel environment variables matches the key used when the record was created. Do not re-encrypt without proper key rotation procedure.
⏱ Probation Alert Not Firing
Problem: Probation ends in 3 days — no alert in /approvals inbox
Cause: Cron job /api/cron/probation is not running or the CRON_SECRET environment variable is incorrect
Fix: SUPER_ADMIN checks Vercel Functions logs for /api/cron. Verify CRON_SECRET matches vercel.json cron configuration. Test manually by calling the endpoint with the correct secret header. Alternatively, manually create the probation decision at /persons/[id] → Probation.
Problem: Cron fires but the decision goes to wrong person's inbox
Cause: workflow_instances approver_id is set to a previous manager before a recent transfer
Fix: Update the workflow template to dynamically resolve the approver from the current worker_assignments.line_manager_id at /settings/workflows. Recall the stale workflow at /approvals → Withdraw and resubmit.
Problem: ARIA is not flagging upcoming probation decisions
Cause: ANTHROPIC_API_KEY missing or expired in Vercel environment, or ARIA context does not include probation intents
Fix: Check /aria for the error banner. If API key is valid, ask ARIA directly: "Show all employees with probation ending this month" — if this fails, check server logs at Vercel dashboard.
📊 Grade Not Appearing in Dropdown
Problem: Grade 7 does not appear in the grade dropdown on the hire form
Cause: Grade 7 exists in the grades table but has no salary band (min_salary / max_salary) — blocked by pre-condition check
Fix: Go to /master-data/grades → Grade 7 → Edit. Enter min_salary and max_salary values. Save. Return to /persons/new — Grade 7 will now appear in the dropdown.
Problem: Grade exists in master data but is greyed out on the hire form
Cause: The grade's legal_entity_id does not match the employee's target entity, or the grade has is_active = false
Fix: Check the grade record at /master-data/grades. Verify it is linked to the correct legal entity and that is_active is true. If the grade should be used across entities, consult HR Director before making it global.
Problem: Salary entered is outside the grade band — system rejects
Cause: Proposed salary is below min_salary or above max_salary for the selected grade (salary band validation)
Fix: Either adjust the offered salary to fit within the band, or request a grade band update from HR Director at /master-data/grades → Edit (HR_DIRECTOR permission required). All band changes are audited.

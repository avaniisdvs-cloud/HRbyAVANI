Section 1
Module Overview & Preconditions
Payroll Processing in AVANIIS HR executes a monthly cycle: build a DRAFT run, validate salary elements, submit for Finance approval, lock the run, generate the WPS Salary Information File (SIF), and submit to the bank. EOSB, DEWS, and GPSSA calculations are computed automatically based on nationality_category and hire_date. Every payroll write produces an immutable audit entry and a GL journal to Oracle ERP.
✅ Preconditions Checklist — All must be true before opening a payroll run
✓
All employees ACTIVE with valid worker assignments
Verify at: /persons → filter: ACTIVE
✓
Salary elements configured for all grades and positions
Configure at: /master-data/salary-elements
✓
Legal entities have bank details and IBAN mapping
Configure at: /master-data/legal-entities
✓
WPS IBAN set per employee (AES-256-GCM encrypted)
Verify at: /persons/[id] → Banking tab
✓
EOSB scheme assigned per nationality_category
Configure at: /master-data/eosb-schemes
✓
GL cost centre mapping to Oracle ERP configured
Configure at: /settings/gl-mapping
✓
Finance approver user role assigned in system
Configure at: /users → role = FINANCE
🚫 Blocking Conditions — System will refuse to process or submit payroll
IBAN missingEmployee excluded from WPS SIF file. Cannot submit WPS without a valid IBAN for every active employee. Go to /persons/[id] → Banking tab and add the encrypted IBAN before run closure.
Payroll run LOCKEDAll changes blocked while run is in LOCKED, APPROVAL_PENDING, or WPS_GENERATED status. Finance must approve or reject before any corrections can be made.
No salary elementEmployee has an ACTIVE assignment but no salary elements linked. System excludes them silently — they will not appear in the run. Configure at /master-data/salary-elements.
nationality_category missingEOSB scheme cannot be determined. System blocks run calculation until all employees have nationality_category set (UAE_NATIONAL / EXPAT / FREE_ZONE_EXPAT).
Payroll period overlapTwo open runs covering the same period and entity are not permitted. Close or void the existing run before creating a new one for the same period.

Section 5
Payroll Run State Machine
A payroll run moves through 8 statuses from DRAFT to PAID. Once LOCKED, no changes are permitted. APPROVED can be rejected by Finance, which resets to DRAFT for correction. CALCULATED can be recalculated from DRAFT. PAID is the only terminal state.

Section 7
Salary Elements & EOSB Calculation Guide
Salary elements are additive components resolved per employee from grade defaults and position overrides. The EOSB scheme is determined automatically from nationality_category. IBAN encryption uses AES-256-GCM — the same cipher as Emirates ID. WPS SIF format requires strict field ordering and IBAN format compliance.
📐 EOSB Scheme Decision Flow — nationality_category drives scheme selection
💼 Salary Element Types
Basic SalaryGrade-band default · used for EOSB calculation
Housing AllowanceFixed or % of basic · taxable benefit
Transport AllowanceFixed monthly · excludes overtime base
Acting AllowanceTriggers when is_acting = true (BR-AC-002)
OvertimeRate × hours · capped per FDL 33/2021 Art. 34
DeductionsAdvances · loan repayments · absence unpaid
ℹ️ Elements are inherited from grade defaults then overridden at position level. Position overrides take precedence.
🔒 IBAN Encryption & WPS Format
EncryptionAES-256-GCM (same as emirates_id)
Storage fieldpersons.iban (enc) — cipher-text in DB
WPS formatAE + 2 check digits + 23 digit BBAN
No spacesAEXXXXXXXXXXXXXXXXXXXXXX (29 chars)
Bank code4-char SWIFT BIC in EDR header record
Emirates ID in SIF18-digit format — no dashes in WPS file
⚠ Bank rejects the entire SIF batch if any single IBAN fails validation. Run the Validation Report before uploading.
📐 Pro-Rata Calculation Rules
Daily ratebasic_salary ÷ calendar days in month
Split pointworker_assignments.effective_date
Old deptdaily_rate × days from 1st to (eff_date − 1)
New deptdaily_rate × days from eff_date to month end
GL splitTwo Oracle cost centre journals, same period
AllowancesPro-rated at same ratio as basic
💡 If GL mapping is missing, system posts 100% to old cost centre and raises a payroll warning in the run log.

Operational Scenarios
Four real-world payroll scenarios from Avaniis / Avaniis operations. Each shows exact resolution steps and the compliance risk at stake.
A
Employee Resigned During Payroll Run
Omar Al Rashidi submitted his resignation on 18 June. The June payroll run is already in CALCULATED status. EOSB must be processed mid-cycle.
1
Do NOT close or lock the June run yet — it is still modifiable in CALCULATED status
2
Navigate to /persons/[Omar's ID] → Actions → Initiate Termination, set effective date 18 Jun
3
System auto-calculates EOSB: hire_date to 18 Jun, TRADITIONAL scheme — confirms AED 42,350 entitlement
4
HR + Finance sign off the EOSB settlement at /approvals (separate from payroll run approval)
5
Payroll run auto-adds Omar's final net pay (pro-rated to 18 Jun) + EOSB payment as separate pay line
6
Submit run for Finance approval — EOSB is included as a payroll line item in the SIF file
⚠ EOSB must be settled within 14 days of termination per FDL 33/2021 Art. 53. If the payroll run cycle cannot accommodate this, process as an off-cycle payment.
Refs: BR-EOSB-001 · payroll_runs.status = CALCULATED · FDL 33/2021 Art. 53
B
WPS File Rejected by Bank
The June WPS SIF file was uploaded to the MOHRE portal but the bank returns error code WPS-ERR-004: Invalid IBAN format for 3 employee records.
1
Navigate to /payroll/[run-id]/wps → View Validation Report — error rows are highlighted in red with IBAN values
2
For each failed employee: go to /persons/[id] → Banking tab and correct the IBAN (remove spaces, ensure AE + 27 digits)
3
The run is in SUBMITTED status — it must be set back to WPS_GENERATED to allow re-generation (SUPER_ADMIN only)
4
Regenerate SIF file — only the corrected employees are updated; net pay amounts do not change
5
Re-upload corrected SIF to MOHRE WPS portal within 48 hours of initial rejection
6
Run status moves back to PAID once bank confirms all 142 records processed
⚠ MOHRE logs every WPS submission. Repeated rejections escalate to a compliance flag on the company's MOHRE employer account. Fix IBAN data once and avoid re-occurrence.
Refs: payroll_runs.wps_file_path · persons.iban (enc) · WPS Ministerial Decree
C
Wrong Salary Applied — Correction Next Run
Fatima Al Zaabi was promoted in May but her June payslip shows her old Grade 6 salary. The June run is already PAID.
1
Verify: go to /persons/[Fatima's ID] → Assignments — confirm Grade 7 effective_date is 15 May
2
Check salary_elements — confirm Grade 7 basic salary element is active from 15 May
3
Since June is PAID, it cannot be modified — system blocks retrospective edits on PAID runs (BR-AUDIT-001)
4
In July payroll run, add an "Arrears" salary element for the May-June underpayment amount
5
Document the arrears adjustment with a note in the salary element description field
6
Finance approves July run which includes the arrears — audit trail shows both the original and correction
⚠ Never attempt to void a PAID payroll run. The immutable audit trail and WPS submission make reversal impossible. Always correct via the next period adjustment.
Refs: BR-AUDIT-001 · payroll_runs.status = PAID · salary_elements (arrears type)
D
New Entity Added Mid-Year — First Payroll Run
Avaniis Hospitality LLC is added to AVANIIS HR in June with 18 employees transferring from Avaniis Holdings. Their first payroll run must be set up from scratch.
1
Create the legal entity: /master-data/legal-entities → New Entity: "Avaniis Hospitality LLC" with bank details and IBAN
2
Configure payroll entity mapping: /payroll → Settings → map Avaniis Hospitality LLC to payroll run template
3
For each transferred employee: submit a Cross-Entity Transfer at /persons/[id] → Actions → Transfer (BR-CE-001) — EOSB settled from old entity first
4
Assign IBAN per employee under new entity banking details at /persons/[id] → Banking
5
Configure GL cost centre mapping for Oracle ERP: /settings/gl-mapping → Add Avaniis Hospitality cost centres
6
Open first payroll run for Avaniis Hospitality LLC for June — pro-rated from transfer effective_date to month end
⚠ EOSB from Avaniis Holdings must be settled or formally carried forward before transfers take effect. System blocks cross-entity transfer until EOSB disposition is documented (BR-CE-001).
Refs: BR-CE-001 · legal_entities · payroll_runs · /settings/gl-mapping · BR-EOSB-001
Section 9
Troubleshooting Knowledge Base
Four common payroll problems with root cause analysis and exact fix steps. Always check audit_log first — every payroll calculation step leaves an immutable record.
👤 Employee Excluded from Payroll Run
Problem: Ahmed's name is missing from the June payroll run employee list
Cause: Most common reasons are assignment_status ≠ ACTIVE, no salary element assigned, or IBAN is null
Fix: Check /persons/[id] → Assignments (must be ACTIVE). Then /master-data/salary-elements (at least one element must be linked to his grade or position). Then /persons/[id] → Banking (IBAN must be set). All three must be true for inclusion.
Problem: New hire is ACTIVE but excluded from their first payroll run
Cause: hire_date falls after the payroll period end date — employee was not active during the run period
Fix: Confirm hire_date vs. period_start and period_end in the run. If hire date is within the period, recalculate the run. If hire date is after period end, employee will be included in next month's run automatically.
Problem: Employee shows in the run list but with AED 0 net pay
Cause: Salary element amounts are all zero — grade salary band may have been set but element amounts not populated
Fix: Go to /master-data/salary-elements → find the element linked to this employee's grade → confirm amount_value is non-zero and effective_start_date is within the run period.
🏧 WPS File Format Error
Problem: WPS portal returns "Invalid IBAN" for multiple employees
Cause: IBAN stored with dashes or spaces; AE format requires exactly 29 characters with no separators
Fix: Go to /persons/[id] → Banking for each failed employee. Update IBAN to AEXXXXXXXXXXXXXXXXXXXXXX format (AE + 2 check digits + 23 BBAN digits, no spaces). Regenerate SIF file after all corrections.
Problem: WPS file rejected — "Emirates ID mismatch" error code
Cause: SIF file uses 18-digit Emirates ID (no dashes) but person record has the formatted 784-YYYY-XXXXXXX-X value
Fix: AVANIIS HR auto-strips dashes when generating the SIF file. If the error persists, check that persons.emirates_id was entered in the correct format. Verify via SUPER_ADMIN at /users → Person Record (PII access required).
Problem: EDR header record bank code invalid
Cause: Legal entity bank SWIFT BIC code is incorrect or has not been set in the entity record
Fix: Go to /master-data/legal-entities → [Entity] → Banking Details. Verify the 8 or 11 character SWIFT/BIC code matches the entity's UAE bank. Update and regenerate SIF. The EDR header is sourced directly from this field.
📐 EOSB Calculation Mismatch
Problem: Employee disputes EOSB amount — says it should be higher
Cause: nationality_category may be set incorrectly (e.g. EXPAT when employee is UAE National) causing TRADITIONAL instead of GPSSA application
Fix: Check /persons/[id] → nationality_category field. UAE nationals must be UAE_NATIONAL. Correct the value, then recalculate EOSB at /payroll → EOSB Calculator → [Employee]. GPSSA employer contributions (17.5%) will be applied from the corrected date.
Problem: EOSB amount is too low for a long-serving employee
Cause: hire_date in persons table is incorrect — entered as start date of current contract, not original hire date across entities
Fix: SUPER_ADMIN corrects hire_date at /users → Person Record with an audit justification. For cross-entity transfers, check the original entity's person record — service may continue from original hire_date if EOSB was not settled at transfer (BR-CE-001 check).
Problem: DEWS contribution not appearing in the run for a JAFZA employee
Cause: Employee's nationality_category is EXPAT not FREE_ZONE_EXPAT, or the legal entity is not flagged as a DEWS-eligible free zone entity
Fix: Update nationality_category to FREE_ZONE_EXPAT at /persons/[id] → Details. Also verify the legal entity is flagged as free_zone = true at /master-data/legal-entities. Both must be true for DEWS to apply.
🔒 Finance Step Frozen — Payroll LOCKED
Problem: Payroll Admin needs to correct a salary but the run shows LOCKED with no edit buttons
Cause: Finance has approved the run — it transitions to LOCKED automatically, making all edits impossible until Finance rejects
Fix: Contact the Finance approver and ask them to Reject the run at /approvals. Once rejected, the run returns to DRAFT status and edits are unlocked. Make corrections, recalculate, and resubmit for Finance approval.
Problem: Finance approver is unavailable — delegation needed
Cause: Primary Finance approver is on leave with no delegation configured
Fix: SUPER_ADMIN or HR Director configures delegation at /settings/delegations. Map the Finance role to an acting approver with a specific date range. The delegated approver will see the payroll approval in their /approvals inbox immediately.
Problem: Workflow approval step is stuck — no one receives the Finance notification
Cause: notification_log table has FAILED entries — SMTP credentials invalid or email quota exceeded
Fix: SUPER_ADMIN checks /settings → Notification Logs (or audit_log for notification_log failures). Verify SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS environment variables in Vercel. Finance approver can still act directly by navigating to /approvals — email is a notification, not a gate.

"Sara transferred departments mid-month — how does this affect her pay?"
ARIA checks in order
1.Retrieves worker_assignments.effective_date for Sara's transfer
2.Calculates days in old dept (1st to eff_date − 1) and new dept (eff_date to month end)
3.Applies pro-rata: daily_rate = basic_salary ÷ calendar_days_in_month × respective_day_count
4.Checks gl_cost_centre_mapping for both old and new departments
"Sara transferred on 15 June. Her daily rate is AED 32,000 ÷ 30 = AED 1,067/day. Old dept (Sustainability): 14 days × AED 1,067 = AED 14,933. New dept (Operations): 16 days × AED 1,067 = AED 17,067. Total basic unchanged at AED 32,000. Two GL journal lines will post to Oracle ERP: one per cost centre. Confirm GL mapping is set for Operations at /settings/gl-mapping."
worker_assignments.effective_date · pro-rata daily_rate · gl_cost_centre_mapping · BR-TR-001
